# WPF 포팅 설계

## 목표

Electron 런타임을 Microsoft Store 패키지에서 제거하고, Windows 10/11에 포함된 .NET Framework 4.8 기반 WPF 앱으로 기존 데스크톱 펫 기능을 옮긴다. 목표 MSIX 크기는 이미지 원본을 유지한 상태에서 2~5MB다.

## 범위

- Windows 10/11 x64와 Microsoft Store 배포만 지원한다.
- 투명·테두리 없는 107×100 창, 항상 위 표시, 작업 표시줄 숨김을 유지한다.
- 대기, 걷기, 서기, 수면, 행복, 드래그 상태와 기존 전환 확률 및 시간을 유지한다.
- 클릭 반응, 하트와 말풍선, 드래그 이동, 화면 경계 반전, 더블 클릭, Esc 위치 초기화를 유지한다.
- 트레이의 일시정지, 항상 위, 자동 실행, 위치 초기화, 종료 메뉴를 유지한다.
- 설정은 사용자 AppData의 JSON 파일에 저장한다.
- 기존 Electron 소스는 비교와 복구를 위해 저장소에 남기되 MSIX에는 넣지 않는다.
- Linux 패키지는 지원하지 않는다.

## 구조

`native/` 아래에 최소 WPF 프로젝트를 둔다.

- `BunnyStateMachine.cs`: 상태, 방향, 마지막 상호작용 시각과 다음 상태 선택을 담당한다. WPF에 의존하지 않는다.
- `MainWindow.xaml` / `.cs`: 이미지 표시, 애니메이션, 입력, 타이머, 화면 내 이동을 담당한다.
- `App.xaml` / `.cs`: 단일 실행, 설정 로드, 트레이 메뉴와 앱 수명을 담당한다.
- `Assets/`: 기존 PNG와 아이콘을 빌드 리소스로 포함한다.
- `StateMachineTests.cs`: 외부 테스트 프레임워크 없이 상태 전환을 검증하는 실행형 테스트다.

새 NuGet 패키지는 추가하지 않는다. WPF, `System.Text` 계열 대신 .NET Framework 기본 직렬화 기능, Windows Forms의 트레이 아이콘처럼 운영체제에 포함된 기능만 사용한다.

## 동작 흐름

앱 시작 시 단일 실행 잠금을 획득하고 설정을 읽은 뒤 화면 오른쪽 아래에 창을 표시한다. UI 타이머가 상태 머신에 다음 상태를 요청하고, 걷기 상태에서는 창을 수평 이동한다. 화면 경계에 닿으면 방향을 반전한다. 사용자 입력은 상태 머신의 마지막 상호작용 시각을 갱신하고 해당 시각 효과를 실행한다.

종료는 트레이 메뉴에서만 수행한다. 창이 예기치 않게 닫혀도 트레이 프로세스는 유지하며, 두 번째 실행은 기존 창을 표시한다. 손상된 설정 파일은 기본값으로 복구한다.

## 패키징

WPF 앱은 .NET Framework 4.8 프레임워크 종속 x64 Release 빌드로 만든다. Store 스테이징에는 실행 파일, 필요한 소형 어셈블리, 이미지, 매니페스트와 Store 로고만 복사한다. Electron의 Chromium, Node.js, 언어팩, 그래픽 DLL은 포함하지 않는다.

기존 Store identity와 publisher 값을 유지하며 현재 WinApp CLI로 unsigned MSIX를 만든다. Microsoft Store가 제출 후 서명한다.

## 검증

1. 상태 머신 테스트를 구현 전에 실패시키고 최소 구현 후 통과시킨다.
2. x64 Release 빌드가 경고와 오류 없이 완료되는지 확인한다.
3. 생성된 MSIX의 파일 목록에 Electron 런타임이 없는지 확인한다.
4. MSIX 크기가 5MB 이하인지 확인한다.
5. 설치 후 시작, 이동, 클릭, 드래그, 트레이 메뉴와 종료를 수동 확인한다.

## 제약과 실패 처리

- .NET Framework 4.8 개발 도구가 없으면 Microsoft 공식 개발자 팩을 설치해야 한다.
- 화면이나 설정 API 실패 시 앱을 종료하지 않고 기본 위치와 기본 설정을 사용한다.
- 원본 PNG만으로 목표 크기를 넘는 경우에만 해상도와 품질을 눈에 띄지 않는 범위에서 줄인다.
